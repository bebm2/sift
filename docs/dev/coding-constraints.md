# 开发约束（软规范）

> 给人与 AI 代理的默认纪律。违反时说明理由；不由 CI 强制。

## 原则

1. **SRP**：一个文件/类型只干一类事；职责膨胀就拆，不堆「工具箱」。
2. **依赖方向**：领域写口保持唯一（如 transition / EmitInterrupt / ApplyCommandEvent）；上层不绕过。
3. **少接口**：只有 ≥2 个真实实现或需要测替时才抽接口；单实现用具体类型。
4. **YAGNI**：不为假想扩展预埋抽象、配置开关、策略表；第二个真实调用方出现再抽。
5. **精简**：能删不旁路；优先改现有路径；新增代码要能指到 spec/issue 需求。

## 体量

6. **生产 `.go`**：>500 行 = 提醒宜拆；>800 行 = 硬劝阻，PR/plan 须写清为何不拆与内聚边界。
7. **`*_test.go`**：无 500 提醒；>1200 行硬劝阻（表驱动可保留，避免为凑行数乱拆）。
8. **拆分标准是边界不是行数**：按域/写口/生命周期拆；禁止为过线把紧密耦合逻辑切碎。

## 复杂度与数据

9. **默认可读**：清晰 > 炫技；热路径或大数据量才优化，并在注释/PR 点明复杂度动机。
10. **按场景选结构/算法**：局部小集合用切片/map 即可；需要有序/去重/公平调度等再用合适结构，并说明取舍。
11. **避免隐性平方**：循环嵌套、重复全表扫描、无界缓冲要有意识；拿不准就量一下或写清假设规模。

## 可维护 / 可扩展

12. **契约在 specs**：行为以 `specs/` 为准；代码注释不复制大段契约，链到规格节。
13. **失败取向一致**：与项目既有 fail-closed / 幂等 / 单写口纪律对齐，不另起平行机制。
14. **测试跟行为**：改契约先改/补测试；不靠「以后补」堆无断言代码。

## AI 编码纪律

15. **范围闸门**：只做 issue / plan / DoD 内的事；PRD「明确不做」、Backlog、复审标 `DEFER` 的默认不实现；finding 无 scope（P0/P1/P2/DEFER）不擅自扩做。
16. **证据门禁**：完成 = 相关测试或约定命令已跑过；禁止「我觉得过了」；禁止删测试、空断言或弱化断言凑绿。
17. **只增不删要解释**：净新增为主时，PR/说明写清为何不能删或合并旧路径；优先收敛旁路而非叠床架屋。
18. **最小 diff**：不顺手大重构、不「顺便清理」、不改无关文件；风格跟随当前文件本地习惯。
19. **不自审通过**：实施者不得把复审写成 PASS；关键路径宜异构复审（见 Phase Loop）。
20. **诚实缺口**：未接线 / 未闭环写明「未实现」；禁止用 schema、壳或单测冒充生产接通。
21. **先读再写**：改前读调用方、邻近实现与测试；禁止凭训练记忆猜 API 或平行再造已有能力。
22. **错误与边界显式**：不吞 `error`；无界 channel/slice/重试要有上限或写清假设规模；不发明平行重试/状态机绕过既有写口。

## 反模式（默认拒绝）

23. 上帝包/上帝文件、为测试层层 wrapper、过早泛型、死代码旁路、复制粘贴分叉代替参数化。
