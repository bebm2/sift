# ADR-004 Gate 是纯函数

结构展开见 [DESIGN §8.5](../DESIGN.md)。本 ADR 是 [PRD §10.3](../PRD.md)（回放集必须与 Gate 同期落地）的实现方式。

## 决策

```
gate(changeFacts, policy, riskScore) → verdict
```

**无 IO、无时钟、无网络、不读文件。** 所有输入由 reconciler 预先取好并冻结成一个快照结构。三条配套推论同属本决策：

1. 影子门禁记录器挂在 Gate 调用点上，**每次调用都记，无开关**；预判必须与「生成 Interrupt + 写发布 operation」**同事务**落下，不得延迟到人回复时补算（那时 Checks 或 base 已可能漂移，补算出的快照与人当时看到的不是同一个世界）；
2. `auto_merge` 的证据门槛在 Gate **之外**判定——由**认证投影**产出类别级资格，组装进**有效策略**；证据不达标即把 `auto_merge` 剔掉，Gate 只看有效策略；
3. 风险评分（T3）作为输入传入，Gate 不调用 Brain。这与 PRD §5.4 把 T3 列在判定顺序之中不矛盾：该处明示是「逻辑顺序，实现可等价」。

判定结果以 **`(gate_input_hash, gate_version)`** 为键缓存，其中 `gate_input_hash` 是**整份冻结输入快照**的规范化序列化摘要。缓存条目、影子门禁记录与回放集引用**同一个** `gate_input_snapshot_id`，不允许「回放集存一份、缓存按另一份判」。

## 认证投影（`auto_merge` 证据门槛的合法数据流）

初稿把证据门槛推到「策略加载期的一次校验」就收手，留下两个洞：账本的读取面被限定为 T7 与指标两个消费者，认证计算无处安放；且「加载期算一次」会让资格随样本增长而陈旧。补一个**确定性**投影：

- 从校准数据按**任务类别**聚合，输出「该类是否通过 PRD §5.6 双向不对称门槛」+ `certification_version`（含统计窗口与阈值版本）；
- 随校准写入增量更新，且**更新与校准写入在同一事务内**（属 DESIGN §6.3 事务四件事中的「预算 / 游标 / 幂等记录」一类；纯统计无 IO，不违反「耗时 IO 不得持有事务」）；有效策略在每次组装 Gate 输入时读当前快照；
- **只产出类别级资格，不接触单条 Run 特征**——这是它与 A7 防火墙相容的原因：A7 禁止的是「你以前都批所以这次替你批」，而按类别认证一个门禁能否自动放行，正是 PRD §5.9 明示允许的聚合层用途；
- 认证版本变化即旧 Gate 缓存失效。

## 理由

**PRD 有一条约束不可能靠纪律维持：回放集不得被延后。** PRD §10.3 已经预判了它是「实现阶段容易被挤掉的隐性工作」，而 §5.6 的阈值认证与 T7 的提案质量全都依赖它。纯函数是把这条约束变成结构的唯一手段：

- 影子门禁记录的就是这个函数的输入快照与输出 verdict；
- 于是「离线回放集」不是一个需要额外排期的导出功能，而是「把库里的输入快照重新喂给同一个函数」；
- 反过来说，**只要 Gate 里出现一行 `await forge.getChecks()`，回放集就会在实现阶段自然死亡**——因为重跑需要复现当时的网络状态，没人会做——T7 随之退化成凭感觉提建议。

第 2 条推论解决的是另一个漂移点。PRD §5.7 要求「配置里写了 `auto_merge` 也不生效」，如果这个判断放在 Gate 内，Gate 就必须读证据统计（有 IO），纯函数性立即破裂。把它前移到策略加载期后，「有效策略」是一个已经过滤过的值，Gate 只看它，不需要知道证据这回事——**同一条需求换个位置实现，就从破坏架构变成免费**。

## 缓存键为什么是摘要而不是维度枚举

D0.2 用的是枚举式键 `(run_id, head_sha, gate_version, effective_policy_hash, certification_version)`。它漏了一半输入（评审 R5-F1）：`head_sha` 只代表代码内容，而同一个 SHA 之下 Checks 会从 pending 变 success 再变 failed（CI rerun）、review/approval 会变、mergeability 会从 `unknown` 变化、riskScore 及其提示词/schema 版本也会变。后果不是缓存效率问题，是**正确性**问题——CI 重新失败后复用此前的放行 verdict，是一条实打实的漏放通道；`unknown` 期的 pending verdict 被永久复用则让 Run 卡死。

改成整份快照的摘要，变的不是维度数量而是**完备性的来源**：枚举式键要求有人在每次新增输入字段时记得同步键，摘要式键让新增字段自动改变键。D0.2 漏掉 riskScore 正是前一种模式的必然产物——它甚至是函数签名上明摆着的第三个参数。

两条配套约束：

- 输入快照必须**显式记录 riskScore 的来源与版本**（T3 正常输出 vs 确定性兜底）。于是 T3 失败期的兜底裁定与 Brain 恢复后的裁定天然落在不同键上，不会把一个本可自动合并的 Run 永久锁在兜底结论上。
- `gate_version` 仍单独入键：它代表判定逻辑本身的版本，不在输入里，摘要覆盖不到。

## 放弃的选项

| 选项 | 放弃理由 |
|------|---------|
| Gate 内部自取 Checks / diff / 策略（最省事的写法） | 直接杀死回放集，连带杀死 §5.6 的阈值认证与 T7；这是本项目最典型的「顺手简化」 |
| 影子门禁作为可开关的旁路记录器 | PRD §3.4 要求 Gate 上线即常驻。有开关就会在忙的时候被关，而它需要的是连续样本 |
| 回放集作为后期导出功能 | 见 PRD §10.3 的需求级禁止 |
| 让 Gate 直接读账本判断认证（省掉投影） | 破坏纯函数性，回放立即失效；且会把「单条历史」引到判定路径旁边，A7 防火墙从此只剩自觉 |

## 后果

- 正面：Gate 可单测、可缓存、可回放三件事一次拿到；影子门禁成本近零（只是记录输入输出）。
- 负面：reconciler 承担「预先取齐全部输入」的责任，取数逻辑集中且必须显式——包括「取不到就是 `unknown`，转 HITL」这条（PRD §5.2 保守交集原则）。
- 中性：Gate 的每次版本变更都必须 bump `gate_version`，否则缓存与回放结论会静默混版。
- **维护义务**：`gate_input_hash` 的完备性依赖「快照即输入的全集」。若将来有输入绕过快照直接进入判定（例如为省一次查询而在函数内读某个当前值），摘要就不再代表输入，缓存正确性静默失效。三参数签名约束了函数侧，`changeFacts` 的组装点需要同一纪律。
