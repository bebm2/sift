# ADR-002 控制循环 + 唯一转移入口

结构展开见 [DESIGN §6.1–6.3](../DESIGN.md)。

## 决策

1. `siftd` 是一个 **reconciler**：每个 tick 读取「forge 事实 + 本地 Run 状态 + 进程实况」，计算差量，**执行一步转移**，落库，结束。不做「轮询发现变化 → 回调链 → 回调里触发下一步」。
2. 全系统只有一个能写 `runs.status` 的函数：`transition(runId, event, expected)`。它内含合法转移表，非法转移**抛错而非静默忽略**，并与事件追加同一事务。
3. 状态更新走 compare-and-set：命令必须携带期望状态或版本号；过期命令成为**可审计的 no-op**。

## 理由

**形态是被需求决定的，不是被偏好决定的。** webhook 被砍掉（PRD §3.2）、事实源在 forge（A2）之后，系统的输入就只有「定期观测外部世界」这一种形式——这正是 reconciler 的定义。三项收益都不是风格问题：

- **崩溃恢复成为结构性质。** 重启后第一个 tick 自然发现「DB 说 `running` 但进程实况不符」并按既有规则收敛。PRD §10.1 的「幽灵 running」被结构排除，而不是被小心处理掉。
- **反向同步（PRD §4.5）不需要专门通道。** Issue 被关闭、Change 被人手动合并，在下一个 tick 就是普通输入，与正向流程走同一段代码。回调式设计会为它长出第二条路径，两条路径必然漂移。
- **一步一转移让状态机可测。** 每个 tick 是纯粹的 `(观测, 状态) → 转移决策`，可喂固定观测跑单测。

CAS 解决的是轮询系统的固有竞态：同一条 forge 观测可能被两个 tick 看到；人的审批指令与 HITL 超时升级可能同时抵达。没有 CAS，这类竞态表现为「状态被旧决定覆盖」——一种事后极难归因的 bug。

唯一入口是 PRD §4.1「所有合法转移必须经唯一校验入口（防止旁路改状态）」的实现方式，且它靠**「没有第二个这样的函数」**保证，不靠 review 记得拦。领域类型显式区分 `Recommendation → DomainCommand → Transition` 三级，使 A1 无法被绕过：LLM 的产物在类型上就不是可执行的东西。

## 放弃的选项

| 选项 | 放弃理由 |
|------|---------|
| 事件回调链 / 内部事件总线 | 每个外部事实需要一条专属路径；反向同步与恢复各自长出第二套逻辑；违反 A4 |
| 纯事件溯源（状态由重放得出） | 调度与 CLI 都需要低成本读当前状态；重放成本不值得为纯粹性支付。折中：事件只追加 + 投影同事务写入（见 [ADR-003](003-transactional-outbox.md) 同族论述） |
| 每模块一进程 / 工作队列中间件 | 单机单用户下无收益，只增加生命周期管理与部署复杂度（C4） |

## 后果

- 正面：恢复、反向同步、可测性三件事共用一套机制；tick 优先级即调度策略，改起来是一处。
- 负面：端到端延迟由 tick 间隔决定，因此 PRD §9.3「打标 → agent 启动 P50 < 60s」依赖自适应轮询表调优；LLM 触点是 tick 派发的异步任务，其结果回流必须再经一次 `transition`，多一跳。
- 需要纪律的地方只剩一处：**不得新增第二个写状态的函数**，这一点由 [DESIGN §12](../DESIGN.md) 的 V1 状态机属性测试守。
