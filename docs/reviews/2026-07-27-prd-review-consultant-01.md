# Sift PRD 评审 · 文字版建议（V0.2）

> 评审视角：产品顾问 office-hours。对象：Sift V0.2「本地多 Agent 任务编排与门禁中枢」PRD。
> 配套：同目录 `2026-07-27-prd-review-consultant-01.html`（8 页视觉版）。本文是纯文字建议稿，可单独转发。

---

## 一、一句话总评

Sift 不是又一个 coding agent，它卖的是 **「筛子 + 注意力调度」**——在人和一堆 Agent 之间立一道确定性门禁，只把真正需要人拍板的事递上来。这个定位我认可，方向对。

但 V0.2 目前的状态是「**架构漂亮、证据不足**」。最大的风险不是设计错，而是**过早平台化、迟迟不验证门禁可信度**。建议先把一道门跑通，再谈 8 个模块。

---

## 二、为什么这个方向站得住（值得做的部分）

1. **反「Agent 万能」的清醒。** 现在满世界堆 Agent 能力，Sift 反过来做「收敛」：LLM 只有发声权、没有决定权（A1 原则）。这恰好补上了 Agent 最被人诟病的那句——「它自己就把事儿办了，你事后才发现办歪了」。
2. **寄生式界面是聪明的省力。** 不自己造 UI、不暴露端口，人留在 forge 的评论/标签里，手机就是审批终端。这把「人要不要装新东西」的成本压到零——而「零采纳成本」是这类工具能不能活下来的关键。
3. **Forge 抽象把部署面压到最小。** gh/glab 当唯一信道、零凭据管理、双平台对称，意味着攻击面和运维面都极小。对「本地 daemon」这种东西，**小就是安全**。

---

## 三、设计上最硬的 3 根支柱（别动）

- **A1 无权柄原则**：所有状态转移 / 门禁 / 合并由确定性代码执行，LLM 只出建议。这是 Sift 的命根子——动了就变回「又一个会乱拍板的 Agent」。
- **Gate 顺序**：`protected_paths → Checks → review_policy → auto_merge`，且用 Shadow Gate 先积累预审证据、再开 auto_merge。顺序和「先证明、再自动化」的哲学要守住。
- **中断结构化**：每次打断人，必须 **≤4 个互斥选项、能念出来**。这是「注意力调度」的落地约束，也是 Sift 和普通通知轰炸的根本区别。

---

## 四、真正要盯的 4 个风险

| 风险 | 性质 | 不处理的后果 |
|---|---|---|
| ① 门禁可信度 | 高影响 / 内部可控 | auto_merge 不敢开，整个「自动化」卖点塌掉 |
| ② 双平台一致性 | 高影响 / 外部依赖 | GitHub / GitLab API 差异导致行为漂移，半夜出 P0 |
| ③ 注意力稀释 | 中影响 / 内部 | 中断太多反而淹没人，Sift 变噪音源 |
| ④ 配置漂移 | 中影响 / 可观测 | 多 repo 策略不一致，门禁形同虚设 |

---

## 五、6 个开放问题 → 建议动作

1. **Shadow Gate 准确率到多少才开 auto_merge？**
   → 先跑 50 次 PR 双盲，预审命中 **≥95%** 再启用；别拍脑袋定 80%。
2. **双平台 API 差异怎么归一？**
   → 抽 `Forge Adapter` 层 + 维护差异矩阵与回归用例；别在业务代码里写 `if github / if gitlab`。
3. **中断频率上限怎么定？**
   → 引入「注意力预算」：每日中断配额 + 超额降级，别让人被 24h 打扰。
4. **多 repo 策略如何保持一致？**
   → 策略即代码，中央模板 + CI 校验，禁止逐仓手改。
5. **失败如何优雅回退？**
   → T6 失败分流三态：**自动重试 / 转人工 / 安全放弃**，别卡死。
6. **Brain 怎么自我标定？**
   → 周级离线回放 + 人工抽检，量化偏差再校准，别让模型悄悄漂移。

---

## 六、下一步建议（我的优先级）

**别先造平台，先跑 PoC。** 验证顺序：

1. **单 repo 跑通 Shadow Gate**（证明门禁可信）；
2. **锁定 Forge Adapter 双平台对称**（证明可迁移）；
3. **定中断预算协议**（证明不淹没人）。

这三件事跑通，比把 8 个模块都做漂亮更有价值。

**PoC 成功标准建议写进 PRD：**
- 单 repo 连续 N 个 PR，预审命中 ≥95%；
- 零误合（false merge = 0）；
- 人日均中断 ≤ X 次。

---

## 七、给 PRD 作者的一句话

V0.2 写得「像架构」，但还差「像证据」。把第 8 节的开放问题从「待定」推进成「**可验证的 PoC 成功标准**」，这份 PRD 就从「好看」变成「能立项」。
