# WBS.md 评审（第 1 轮）

> 日期：2026-07-28  
> 评审人：**kimi-code**（Kimi Code CLI）  
> 评审对象：[`docs/WBS.md`](../WBS.md) D0.1（796 行，对应 DESIGN D0.10 / PRD V0.8）  
> 评审依据：[`docs/PRD.md`](../PRD.md) V0.8、[`docs/DESIGN.md`](../DESIGN.md) D0.10、ADR 001–013、[review-18](2026-07-28-design-review-kimi-k3-06.md) §7 复评条件 2（WBS 落成时的重点携带项）  
> 评审重点：（a）review-18 点名的携带项是否都在；（b）PRD §13.1 六条拍板约束与 PRD 模块表是否全部有落点；（c）验收阶段与切片的时序自洽（测试编号标称的验收里程碑，其依赖机制是否已存在）

## 1. 结论

**暂不通过：两项 P1，补齐后复评。**

WBS 对既有机制的转述质量很高——review-18 点名的携带项全部在（§2 逐条核销），动词集、状态机、恢复与仲裁等关键机制无稀释。但逐项对照 PRD 模块表与 §13.1 时发现两块**整片缺席**的工作：Brain 模块（T1–T6 + 调用壳 + `specs/brain.md`）没有任何实现任务，而 M4/M5 多处引用它的产物；PRD §13.1 六条拍板约束之一「敏感配置启动期读入 + 指纹校验、不热加载」既不在 H1–H15 也无任务落点。WBS 是执行的依据，缺席即不会发生，故定为阻断。

另有 P2 三项（V5 验收阶段错配、launcher 接缝缺席、指标打点缺席）与 P3 七项，见 §4、§5。

## 3. P1 发现

### F1 · P1：Brain 模块整片缺席——T1–T6 触点、统一调用壳、`specs/brain.md` 均无任务

**位置**：全文缺席；被引用处：WBS:167（闭环含「分派」）、415（Gate 判定顺序含「T5 分诊 → flaky 重试」）、421（「风险评分（T3）作为输入传入」）、457（回放集含「Brain 触点 trace」）、542（「每日 token 上限（Brain 调用壳收费）」）。

Brain 是 PRD §8 模块表与 DESIGN §8.3 的正式模块：统一调用壳（decode gateway 校验 → 重试一次 → 确定性兜底）、T1 体检、T2 分派、T3 风险评分、T4 决策简报、T5 失败分诊、T6 打扰调度、token 收费口、提示词版本化。WBS 中：

- 没有任何一个里程碑创建「Brain 调用壳」，但 M5 的 token 预算（542）把收费口挂在它上面—— dangling reference；
- M4 的 Gate 判定顺序引用 T3 的 riskScore 与 T5 的分诊结果（415、421），但无人实现 T3/T5；
- M5 的 Interrupt 需要 T4 产出 `headline` / `brief` / `options`，5.1 只写了发射器的结构校验，简报的生成者缺席；
- M1 的 fake 闭环（167）含「分派」一步，分派者是谁未定义；
- 五个「需要先写的 spec」清单（M1/M2/M3/M4/M5）均无 `specs/brain.md`，而 DESIGN §15 待写清单（1203）列了它。

注：此缺口部分源自 DESIGN §13 切片表本身未给 Brain 独立位置（§8.3 有模块、§15 有 spec，切片无其名）——WBS 继承了它，但 WBS 是把工作变得可执行的最后一站，必须在这里显式安置。建议：T1/T2 随 M2 摄入链、T3/T5 随 M4、T4/T6 随 M5（或单列一片），并补 `specs/brain.md`。T7 提案机制 PRD §5.9 已明示留待后续，不在此列。

### F2 · P1：敏感配置「启动期读入 + 指纹校验 + 不热加载」无落点

**位置**：H1–H15 未收录；任务分解全文缺席。

PRD §13.1（934）把「敏感配置启动期读入 + 指纹校验，运行期不热加载」列为六条拍板约束之一（承载 TM6 缓解），PRD §9.1（762）与 DESIGN §9.1（683）均展开：allowlist、配额、Agent 定义、全局缺省策略启动期一次性读入并做指纹校验，发现磁盘变更即告警并拒绝生效，改动须重启 `siftd` 才生效。WBS 只覆盖了同族的 hooks 指纹（3.7）与 `operator.token` 读入（1.6），**配置本身的读入时机、指纹与不热加载语义没有任务**。这是 WBS 自称「硬约束全部来自 PRD 与 DESIGN、不做新增设计决策」的对偶失误：没新增，但漏了一条已拍板的。建议列入 H 表并安置到 M1（配置体系）或 M2（allowlist 消费前）。

## 4. P2 发现

### F3 · P2：V5 验收阶段标 M3，但 Gate 第 4 片才存在

**位置**：M3 验收表末行「`.sift/**` 硬护栏拦截｜V5」（397）；汇总表 V5 行「对应测试切片 M3、验收阶段 M3 验收」（750）；A5「验收切片 M3」（773）。

V5 是 **Gate 安全测试**，其核心断言（`.sift/**`、CI 配置被硬护栏拦下且不可软豁免、head SHA fail closed）全部由 Gate 执行，而 Gate 属第 4 片（H5）。M3 结束时系统里没有任何能「拦下」的函数。WBS 自己也把 V5 的编写任务放在 M4（433），但 M4 验收标准表（475–483）却没有 V5 行——于是 V5 写成于 M4、验收挂在一个它不可能通过的里程碑上。同理 A5 的「M3」应改 M4。注：V5 中「base 策略与 context 读取源」一条确可在 M3 验证，若有意拆分应显式分两行，而不是把整个 V5 标到 M3。

### F4 · P2：launcher 间接层（ADR-007 的 V0 接缝）无任务

**位置**：M3 任务分解缺席。DESIGN §8.4（519）：「启动 agent 只经单一 launcher 函数，V0 为恒等实现，将来包 `sandbox-exec` / 容器只改这一处」；同段「Agent 启动参数不得假设与 daemon 同环境」WBS 收了（7.1，627），唯独接缝本身没收。ADR-007 的 V0 处置是「不实施沙箱、**只留接缝**、前置 spike」——spike 在 7.3，接缝无人留。这是典型的「实现阶段会被顺手简化掉」项，恰是 DESIGN §1 点名要防的类型。建议在 M3 3.1/3.2 补一行。

### F5 · P2：PRD §10.2 指标打点无任务

**位置**：全文缺席。PRD §10.2 要求八项指标 **V0 就打点**（836–854），DESIGN §9.3（741）明确「全部从事件流与账本派生」，北极星口径为加权打扰次数 / 已合并 Change（权重表为配置项）。WBS 无一处安置指标派生工作；`sift ps` 显示配额余量（5.4/§8.10）只覆盖其中一项。另 PRD §9.3 的 P50 < 60s 延迟要求也无任何测量与验收落点。建议在 M5（事件流与预算齐备后）或单列任务补指标派生，并把北极星权重表列入 `specs/config.md` 默认值。

## 5. P3 发现

1. **M1 验收表缺 V12 与 V9 行**（184–193）：汇总表把 V12（零配置启动）与 V9（端到端）的验收阶段都标为 M1（754、758），M1 验收标准却无此两行；且 M1 把 fake 闭环降为「开发者本地手动验证」（193），与 V9 作为可重复执行的端到端测试的定位不一致——fake 半链理应进 CI。
2. **V10a 验收阶段标「M1 验收」不完备**（755）：其断言集含 wrapper instance/session/permit 交叉拒绝、`spawning` 报告 `not_ready`、指令 `options[]` 校验（DESIGN §12），分别依赖 M3 与 M5。M5 验收表（572、575）确实复用了 V10a，建议汇总表改标「M1 起持续」，与 V2/V4 的标法一致。
3. **M4 前置自相矛盾**（406 vs 469）：前置要求「`specs/gate.md` 已编写」，M4 自己的「需要先写的 spec」又列了 `specs/gate.md`。二选一。
4. **枚举式清单不全但看似全集**：
   - 3.5 恢复矩阵（349–362）声称「实现全部 attempt 阶段的恢复动作（DESIGN §10.1 矩阵）」，但缺：`spawning`（Agent 已落盘、进程与 result 都不在）、`running`（heartbeat 过期 → 限时探测 fail closed）、`running` 后端会话在/不在两行、任意（多 wrapper 竞争同一 attempt）、任意（旧 generation wrapper 苏醒）（DESIGN:773、779–784）。
   - M6 故障注入清单（594–601）缺 DESIGN V4（888）的：同代双 wrapper、permit 后暂停旧 owner、spawn 后证据缺失与进程组残留、PID/PGID 复用防护、**四发现者并发时始终只有一条待决 Interrupt / 一次配额消耗**。
   建议要么补全，要么在清单头部显式标注「全集以 DESIGN §10.1 / §12 为准，此处不复制」——与本文档自己的「引用不复制」纪律一致。
5. **M8 前置「连续稳定运行 ≥ 3 天」无出处**（678）：PRD/DESIGN 均无此要求，与 WBS「不做新增设计决策」的声明冲突。要么给出来源，要么删除。
6. **`sift doctor` 两处清单均缺「策略漂移横向对比」**（153、714–720）：PRD §5.7 与 DESIGN §8.10（664）均要求。
7. **两处小归因/遗漏**：1.2 表清单标注「表结构（DESIGN §7）」，但 `intents` 与 `gate_snapshots` 并非 §7 的命名数据组（表级设计本是 `specs/storage.md` 的自由度，归因失真而已）；M5 未点名「`startup_stall` 禁用 `auto_reject`、达上限落 `hold`」（PRD §4.2），`options[]` 校验与封顶规则虽在（529、516），这条 reason 级禁令建议显式列入 `specs/interrupt.md` 任务。

## 6. 对抗复查通过项（抽查无问题区）

- **最小动词集**：2.1 的 13 个动词与 PRD §5.2 逐一核对，名称、签名、actor 必填标注完全一致。
- **状态机转移表**：1.3 的九条转移与 PRD §4.1（含 V0.6/V0.7 增补的 `queued → waiting_human` 与迟到事实回边）一致，无多无少。
- **spawn handoff**：3.2 的五步压缩自 DESIGN 八步表，无语义丢失；五性质逐条对应。
- **关键机制无稀释**：merge 远端 CAS（2.3）、Change marker 全状态对账（2.2）、一次打扰五件事同事务（505）、生成去重键（503）、nonce 轮换（518）、三类预算各一收费口（5.5）、凭据不进环境变量（331、552）均准确转述。
- **人工验收 A1–A10**（767–779）与 PRD §10.1 十条一一对应；自动化 / 人工两组拆分符合 DESIGN §12「两组都是发布条件」。
