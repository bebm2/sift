## 总评

PRD 的需求层**设计正确性已经到顶**，同意四审与第五轮的判断。但**流程上不建议现在冻结**：四审自己列出的 NEW-1 ~ NEW-5，在它成文之后的 PRD 修订版里**一条都未被修复**——「可以冻结」的结论与其自身证据不匹配。冻结一份自相矛盾的文档，等于把解释权留给实现阶段，而这正是这份 PRD 全文都在防的事。

本轮三件事：

1. 对最新增补（A7 / §5.9 校准账本）的独立评价；
2. 对四审 NEW-1~5 的逐条对账（基于 16:11 版 PRD 验证）；
3. 在 NEW-3（TM6 架构分叉）上补一个四审没说的中间解。

## 一、A7 / §5.9 校准账本：全部六轮里最值钱的一次增补

比 TM6 还值。三个理由：

1. **立论方式正确。**「这是数据采集决策，不是功能决策」——字段今天不写，半年后就是半年的废数据。与 §10.2「指标 V0 就打点」、§3.4「早做便宜、事后昂贵」同源，把「V0 不做学习」和「V0 必须埋数据」干净分开。很多产品死在混淆这两者上。
2. **样本量论证把克制从态度变成了必然。** §5.9 末段——单用户尺度下连二元门禁判断都要几十个负样本才勉强认证，per-path 偏好模型统计上不存在第二个选项——比任何「我们谨慎」的表态都硬。A7 由此从一条自律原则升级为可辩护的工程结论。
3. **公理体系无缝隙。**「A1 管单次调用，A7 管跨时间累积」——学出来的偏好模型不经过 LLM 调用，A1 确实管不到它，单列 A7 是必要的，不是修辞。

**一处建议交叉引用**：§5.9 账本记录「人的响应间隔」作为注意力调度特征，这本身没问题；但 §10.2 刚明确否定过用响应间隔度量注意力消耗。建议在账本那行加半句「仅作调度特征，不作 §10.2 成本口径」，防止未来某个实现者拿着现成字段图省事。

## 三、NEW-3 的中间解：四审的二元框架不必接受

四审把 TM6 收口框成二选一：「零凭证的便宜（复用本机订阅 agent）」vs「真安全的贵（沙箱）」。**这个分叉有中间解，DESIGN 不该一上来就接受二元框架。**

拆开看：沙箱隔离的目标是切断 Agent 到 `~/.sift/`、`gh`/`glab` keychain、共享 `.git` 的通路；而「复用本机订阅」只需要把 **agent CLI 自己的凭证**（如 `~/.claude/`）挂进沙箱——**forge 凭证不挂**。如此：

- §5.2「零凭证管理」的收益（指 forge 侧）基本完整保留；
- TM6 的大半暴露面（allowlist 改写、forge CLI 继承鉴权、git hooks 投毒）同时闭合；
- 真正退化的只是「Agent 与 Sift 同环境」的便利性，不是价值主张本身。

**建议**：开放问题 #13 增列候选方案「挂载最小凭证集的沙箱（仅 agent CLI 凭证，不含 forge CLI）」，并将其决策时机从「Backlog 立项时」提前到 DESIGN——因为它会反过来改写 §5.2 收益表的措辞（「零凭证管理」是否需要加星号，取决于此）。

## 四、结论与冻结前清单

**需求层设计正确性：已封顶。** A1–A7 公理体系自洽，TM1–TM6 威胁模型的诚实度超过大多数商用产品文档，§5.9 补上了最后一块概念缺口。后续评审的边际收益已低于实现反馈，继续评审不如开工。

**但冻结前必须先清掉三处**（全部一行级）：

1. **NEW-1**：统一 §4.2 / §5.5 的 severity 映射公式（两处都写成含「升级次数」的四元组，或单点定义、他处引用）；
2. **NEW-2**：§4.2 给 `escalate` 加次数上限与终态（升级次数达上限 → `auto_reject` / `failed`），并在映射公式中写明「超过上限即封顶」；
3. **NEW-5a**：§10.1 安全验收行加「repo 级护栏（TM2/TM3）」限定词。

NEW-4 的指纹措辞澄清与 NEW-3 的候选方案增列可并入同一次提交。

清完之后：**打 tag，冻结 V0.2，开写 DESIGN.md / WBS.md**。DESIGN 的第一个议题应是 #13 的最小凭证沙箱；WBS 的硬里程碑应是「回放集与 Gate 同期」（§10.3）与「影子门禁 day-1 常驻」（§3.4）——这份 PRD 最值钱的几条约束，都是容易被实现阶段「顺手简化」掉的那种。
