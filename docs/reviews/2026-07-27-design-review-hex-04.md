## 1. 结论

**D0.2 已逐条闭合前三轮的全部 P1 阻断项，复核确认成立。文档可进入 WBS 拆解 / 实现准备。**

本文（笔者第 4 轮）不重复 F1–F6、N1–N3 的逐项复核（见 review-02、review-03），而是聚焦两点：(a) D0.2 是否真正把前几轮的 P1 用结构性机制消化（而非措辞补丁）；(b) 我首轮 review-01 留下的 specs 级项与 §14.5 文档治理声明是否准确。

结论：P1 阻断项确实被结构性消化（见 §2），我首轮 specs 级项也落实（见 §3）。但 review-01 的 5 项 P2/P3 仍悬而未决，且 §14.5 的「三轮评审全部采纳，无驳回」表述不准确（见 §4）。这些均非阻断，但值得收口。

## 2. P1 阻断项的结构性消化（确认）

D0.2 不是措辞补丁，而是把每条发现升级为结构性保证或显式声明：

- **控制面越权（F1）**：双 socket 双能力（`siftd.sock` 运维 + `run.sock` 报告）+ operator capability + ADR-008，且 **V10 用「诚实测试用例」锁死「未闭合边界必须被 doctor 报告」**——这是本轮最佳项，与 Q6（如实可见）自洽：测试断言的是「暴露面被诊断报告」而非「已闭合」，态度诚实。
- **outbox「恰好一次」（F2）**：逐类副作用幂等协议表（6 类）+ Channel 如实降级为至少一次 + agent 启动改 claim 互斥，且被正确标识为表中唯一需要互斥（而非幂等收敛）的类别。
- **`auto_merge` 认证数据流（F3）**：新增**认证投影**为账本第三（聚合级）消费者，且保全 A7 防火墙（认证不接触单条特征，只签名约束类别级）。
- **启动崩溃窗口（F4）**：attempt 生命周期独立建模 + 恢复矩阵补四行分支（`claim 未落、无进程` / `claim 在但进程不在` / `多 wrapper 竞争` 等）。
- **手工合并 / `done` 冲突（F6）**：回 PRD V0.3 裁决（`gate_bypassed` 审计属性 + 门禁绕过率），已实装到 PRD §4.1 / §10.2。

以上与 review-02（F1–F6）、review-03（N1–N3）的复评通过条件逐一核对，全部满足。

## 3. 我首轮 review-01 的 specs 级项（确认已落实）

- **run token 不出环境变量**：run token 移入 `control.json`（0600），环境只留非机密 `SIFT_RUN_DIR`（对应 R1-3.2）。
- **影子预判与 Interrupt 生成同事务**：§8.5 强制同事务（对应 R1-3.3）。
- **doctor 退出码**：定为 0/1/2，下沉 specs（对应 R1-3.1/3.4）。
- **P1-2（A7 防火墙措辞越级）**：经 review-03 裁定本就正确——A7 的「代码里没有任何函数能让历史一致率影响门禁」是对 T7「只提案不生效」纪律的正确描述，实为 F3 的子症状，已在 review-03 澄清，非越级。

## 4. 仍悬而未决（均 P2/P3，无阻断）

这些本质是「留待 specs / WBS 的明确化」，但当前文档没写，且未被 §14.5 处置表覆盖：

1. **P1-3（我首轮，仍完全未处置）**：§14.2 仍声称所有开放数值「都有确定性默认值」，但**全文无默认值表、也无零配置启动的验证项**。PoC 标准之一是「拒绝启动而非降级」，默认值若缺失会直接拒启。建议补一张小表 + 一项「零配置可启动」测试。
2. **P2-1（critical 熔断场景缺测试）**：PRD §5.5 点名的「CI 事故 → critical 洪水 → 熔断」场景，V1–V11 仍无专用测试。
3. **P2-2（回放集范围歧义）**：回放集是否含 Brain 触点 trace（PRD 要求能重跑 Brain 提示词改动）仍歧义——§7 / §8.5 只说 Gate 输入快照，Brain trace 是否进回放集未写明。
4. **P2-3（配置重载边界未写明）**：全局敏感配置「重启生效」vs 项目策略「每次评估重读 base」的不对称是刻意还是待定？文档没说清（关系到 TM2 语义）。
5. **P2-5（T3 移出 Gate 未回写）**：T3 被移出 Gate 的 refine（DESIGN §8.5 vs PRD §5.4）未回写 PRD 或记入 §14.4。

## 5. 文档治理缺口（值得修一下）

**§14.5 的「三轮评审全部采纳，无驳回」不准确。** 我首轮 review-01 的 P1-3 与 P2-1 / P2-2 / P2-3 / P2-5 既未进处置表、也未被 review-03 给出结论，处于盲区——读者会误以为这些已闭环。

建议二选一：
- 把上述 5 项补入 §14.5，标 `carried / 留待 specs`；或
- 将「三轮评审全部采纳，无驳回」改为「本表所列项全部采纳，无驳回」。

否则 §14.5 会营造「全部闭环」的虚假完成感，违反 Q6（如实可见）的自身原则。
