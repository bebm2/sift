## 二、我上次提的点，哪些被接住了（该给的 credit）

1. **「过早平台化、迟迟不验证门禁可信度」** → §3.4 + §10.1 直接回应。证据获取顺序写清楚「影子门禁第一天就后台开录、双平台是结构性决策越晚越贵」，这个并行模型是对的、且非显然。
2. **「Shadow Gate 跑 50 次双盲 ≥95%」** → 被**更好的东西取代**：§5.6 认识到「九成变更本就该放行，永远说通过的门禁一致率也有九成却毫无价值」，于是用**漏放（唯一致命指标）vs 误拦（可宽松）**的不对称 + **负样本绝对数量下限**来定阈值。这比我给的固定数字深，credit 给作者。
3. **「注意力预算」** → §5.5 完整落地，含「禁借支」这条铁律——透支一次就等于承认配额是摆设，这句话写得好。
4. **「策略即代码 + 漂移防护」** → §5.7，且最后一条「让策略文件无法单方面绕过门禁证据」把闭环锁死了。
5. **「PoC 成功标准写进 PRD」** → §10.1 八条，且北极星定为 **Human 分钟数 / 已合并 Change**、质量红线定为 **误放行率**——对一个叫「筛子」的产品，优先级完全正确。

结论：作者不是把我的建议贴进去，是**吃进去后长出了更硬的东西**。这种自我批判的「> 对 V0.x 的批评」callout 习惯，是这份 PRD 在纸面上最值钱的部分。

## 三、现在最硬的地方（新 strengths）

- **§5.6 不对称阈值**：基率问题的处理水平远超同类 PRD。能证明自己「筛得准」比「筛得快」重要，且用负样本下限防止小样本假证——这是真懂统计。
- **§4.2 `on_expire` 永不允许 `auto_approve`**：「超时是人没看见，不是人同意了。」一句话堵死最危险的失败模式。
- **§4.3 / §11 红线 `min_modality: visual` 永不开放语音放行**：防的就是「人批准一个自己没看 diff 的合并」——这正是该产品最该防、最容易被炫技带偏的事。
- **§7.1 指令解析用确定性解析器、不用 LLM**（只有 `/sift ask` 进 LLM）：把「裁定」严丝合缝地锁回 A1，没留后门。
- **§10.2 指标打点从 V0 就开始**，不等 PoC 后——正确，否则回头补指标永远补不上。

## 四、还剩的 / 新冒出来的风险

**1. PoC「负样本≥1 次拦下」≠ 自动合并认证（最该厘清的一条）**
§10.1 要求 PoC 至少拦下 1 个本不该合并的变更——这是**演示机制**；而 §5.6 说阈值认证必须满足**负样本绝对数量下限**。两者性质不同。风险是：有人把「PoC 拦了一次」误读成「auto_merge 现在安全了」。建议在 §10.1 或 §12-3 显式写明：PoC 的「负样本」只证明门禁**会拦**，不证明阈值**已达标**，启用 auto_merge 仍需过 §5.6 的硬门槛。

**2. 回放集（§5.6）必须升为构建里程碑，不是概念**
T7 校准提案的数据源就是影子门禁的回放集；而原文说「没有回放集，T7 就只是在凭感觉提建议」。但回放集是容易被实现阶段挤压的「隐性工作」。一旦 DESIGN/WBS 不把它列为早期里程碑，T7 就会 starving。建议：在 WBS 里把它钉在 Gate 实现同期。

**3. 三重预算的降级态交互没写清**
§9 同时有 token 上限 / API 上限 / 注意力配额。设想：token 没超、但注意力配额耗尽——系统进入「纯确定性模式」却仍想打断人，此时 T6 怎么和配额交互？目前三者独立生效，但**交叉降级态**的语义空缺。建议补一张「预算交叉降级矩阵」。

**4. §3.4 的纪律必须活进 DESIGN.md，否则只是漂亮的一节**
「证据获取顺序」是 PRD 级承诺。若 DESIGN.md（待写）没把它落成架构约束（例如影子门禁是 day-1 常驻后台记录器、而非某个阶段），这节就会变成「写得好但没人遵守」。PRD 自己列了 DESIGN/WBS 待写——提醒：别让这节在落地时蒸发。

**5. 误拦宽松 ↔ 注意力配额 的内在张力**
§5.6 把误拦放宽松，但宽松的误拦会浪费 Interrupt 配额，反过来和 §5.5 打架。两个阈值要**一起调**，建议标注二者的耦合关系。

**6. MCP 模块的信任边界（低，但提一句）**
Agent 是外部进程、MCP 是上报通道。确保 MCP 表面不悄悄变成「第二个隐含的 LLM/信任边界」——保持它只是时间线与 HITL 触发，别让它承载裁定。

## 五、给作者的下一步（优先级）

1. **立刻补一句话**：PoC「负样本≥1」= 演示机制；auto_merge 启用 = 过 §5.6 下限。堵住最危险的误读。
2. **回放集钉进 WBS 早期里程碑**，和 Gate 同期，别让它 starving 导致 T7 凭感觉。
3. **DESIGN.md 动笔时，把 §3.4 的并行证据模型写成架构硬约束**（影子门禁 day-1 常驻）。
4. **补三重预算的交叉降级矩阵**，别留语义空缺。
5. **保持「自我批判 callout」习惯**——这是你在纸面上的护城河，比多一个模块值钱。

## 六、总评（更新）

上次总评是「方向对、架构漂亮、证据不足」。这次修订把「证据不足」这块补了一大半：**取证顺序、PoC 八指标、不对称门禁阈值、注意力预算、漂移防护**全都落地了。剩下的问题不再是「设计错」，而是**几处交叉语义没写清 + 隐性构建工作（回放集）容易被挤压**。

从「好看」到「能立项」，这版已经跨过线了。下一步不是再加模块，是把上面 5 条收口。
